# Paper II — comparison protocol

How every reported comparison in this lane is constructed. The short version:
**methods are compared at fixed accuracy, never at a fixed threshold**, and every
axis except the structural rule is locked across the arms being compared.

Codex and any other executor should treat this as the contract a reported number
has to satisfy. If a number in the manuscript cannot be traced to a cell built
this way, it is not evidence.

---

## 1. Why not compare at a fixed threshold

Each adaptive method carries its own activation threshold — the McLachlan
distance cut `L²_cut` below which it stops growing the ansatz. The obvious
comparison is to set both to the same value. That is not sound here, and the
reason is measured rather than assumed.

Sweeping the threshold over a 100× range (1e-2 → 1e-4) on three drives:

- tightening it improves accuracy **monotonically on 1 of 3 drives** for the
  comparator and **0 of 3** for this route;
- a 100× threshold change moves support by only **~10 coordinates**;
- on the weak slow drive at cuts 1e-2 and 3e-3 the two methods return
  **byte-identical results**, because neither ever triggers.

So the knob has a dead zone, then a live zone, and is non-monotone inside it.
Extending the ladder to 3e-6 does not fix this: AVQDS on the fast weak drive
runs 5.58e-4 → 3.78e-4 → 8.94e-4 → 4.28e-3 → 1.25e-3 → 2.01e-4 as the cut
tightens, and this route is similarly non-monotone.

Reading a method's quality off one setting of its own dial is therefore
meaningless. Any single-threshold comparison in this lane is superseded.

## 2. Locked axes

A comparison may vary **the structural rule and nothing else**. Everything below
is held identical across the arms being compared, composed from
`pipelines/time_dynamics/paper_ii_runs.py` and dumped in full by
`agent_guidance/time-dynamics/paper-ii-run-parameters.md`.

| axis | what is locked | current value |
|---|---|---|
| Physics | seed, regime, drive, reporting grid | `hh_snake_nph1`, six drives, t=10 / 251 checkpoints |
| Inner numerics | integrator, Tikhonov ridge, damping, pinv rcond | rk4, 1e-7, 0.0, 1e-10 |
| Step control | which quantity bounds the step | see §3 |
| Candidate pool | membership and order | 125 deduplicated words, cap 128 (non-binding) |
| Guards | enumeration and certification budgets | 50000 / 12 / 2, insertion batch 1 |
| Activation | `L²_cut` | swept per cell, see §4 |

`test/test_paper_ii_runs.py` asserts that every registered command parses
against the runner's live CLI and that arms differ only in their own flags.
`run_lock.py::assert_comparable` refuses to aggregate runs whose physics differs.

## 3. Step control is an axis, not a property of a method

Both methods bound their step; they differ in the quantity bounded.

| control | bounds | value |
|---|---|---|
| `state_motion_1e-2` (this route) | state displacement per step, then subdivides | 1e-2, subdivision budget 10 |
| `delta_theta_5e-3` (AVQDS) | `max_μ |θ̇_μ| · dt` | 5e-3 |
| composed (new) | both simultaneously | `--solve-repair-parameter-step-max` |

These are separable from the structural rule and must be paired deliberately.
Measured relevance: under state-motion control alone the three largest
step-to-step jumps carry **72–81%** of total error growth; under δθ control,
**7%**. And the integrator matters independently — rk4 beats Euler by ~3.5× for
*both* methods, so an Euler arm may not be compared against an rk4 arm.

## 4. The fixed-accuracy protocol

For each cell (drive × arm):

1. Run a threshold ladder: `1e-2, 3e-3, 1e-3, 3e-4, 1e-4, 3e-5, 1e-5, 3e-6`.
2. Record mean |ΔE| against the exact time-ordered trajectory and the final
   support size `N_θ` at each rung.
3. Report the **cheapest rung meeting the accuracy target** — fewest
   coordinates among those with mean |ΔE| ≤ ε — and the support size there.
   That support size is the comparable cost number.
4. A cell that no rung reaches is **NOT CONVERGED**. That is an outcome to be
   reported, not a gap to average over.

Default target ε = 1e-4. Generated by:

```bash
PYTHONPATH=. python3 -m pipelines.time_dynamics.accuracy_target_report \
    --root output/frontier --target 1e-4
```

### Selection bias — state it, do not hide it

Taking the best rung per arm is a minimum over a noisy ladder, and with
10–100× swings between adjacent rungs it rewards whichever arm was luckier.
This is acceptable **only because both arms receive an identical ladder and an
identical selection rule**. Two consequences:

- report the tightest-rung comparison alongside the best-rung one, since the
  tightest rung involves no selection;
- do not quote a best-rung ratio as a headline figure.

## 5. Reporting contract

Per cell: drive, arm, step control, inner numerics, ladder rung chosen, mean and
max |ΔE|, mean |Δn_d|, final and peak `N_θ`, insertion/deletion/exchange counts,
certification attempts and budget exhaustion, and wall time. Per arm: cells
converged out of cells attempted.

Observable panels follow the form used in this literature: observables against
the exact trajectory plus a resource count. Per-observable deviation is **not**
plotted against time — it is observable-dependent, so the same pair of runs can
be made to look better or worse by choosing which observable to difference. The
standard error metric is state infidelity, available via `--record-statevector`.

is supported.
